# MON-001: Запуск мониторинга при старте приложения

## Описание
Мониторинг системных ресурсов (CPU/RAM/GPU) запускается только при старте сервера llama-server. Нужно чтобы мониторинг работал сразу при запуске приложения и обновлялся независимо от статуса сервера.

## Контекст
Приложение — десктопный лаунчер LLM-сервера на tkinter. Мониторинг реализован через `MonitorThread` (threads.py), который опрашивает ресурсы каждые 2 секунды через subprocess/ctypes.

## Текущее поведение
- `MonitorThread` запускается в `_on_start()` (app.py:355) — после запуска сервера
- Останавливается в `_on_stop()` (app.py:399) и `_check_process_alive()` (app.py:370)
- Мониторинг НЕ работает, пока сервер не запущен

## Желаемое поведение
- Мониторинг запускается сразу при открытии окна приложения (в `__init__`)
- Работает постоянно, не зависит от статуса сервера
- Останавливается только при закрытии приложения (`_on_close`)

## План реализации
1. Вызвать `self._start_monitor()` в `__init__` после `_build_ui()` и `_update_button_states()`
2. Убрать `self._start_monitor()` из `_on_start()` — дубликат
3. Убрать `self._stop_monitor()` из `_on_stop()` — монитор не должен останавливаться при остановке сервера
4. Убрать `self._stop_monitor()` из `_check_process_alive()` — монитор не должен останавливаться при краше сервера
5. Добавить `self._stop_monitor()` в `_on_close()` — остановка только при закрытии приложения

## Известные факты для будущих задач
- MonitorThread использует `root.after(0, ...)` для thread-safe обновления UI
- Мониторинг опрашивает: CPU через `wmic`, RAM через `kernel32.GlobalMemoryStatusEx`, GPU через `nvidia-smi`
- Все вызовы subprocess используют `creationflags=subprocess.CREATE_NO_WINDOW` для скрытия окон
- Приложение использует только стандартную библиотеку Python (zero dependencies)
- Архитектура: Tkinter GUI + daemon-потоки (LogReaderThread, MonitorThread)
